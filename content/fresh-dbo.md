# fresh-dbo — DB 오브젝트 변경 감지 동기화 스킬

## 한 줄
Oracle/Tibero 스키마의 DB 오브젝트(프로시저·함수·패키지·테이블·뷰 등)가 마지막으로 가져온 시점 이후 바뀌었는지 감지해, 로컬 DDL 파일을 최신 상태로만 갱신하는 단일 목적 Python 스킬. 사내 레거시 시스템을 LLM 위키로 문서화할 때, 위키가 읽을 DDL 입력을 신선하게 유지하는 게 목적이다.

## 배경
레거시 시스템을 LLM이 한 객체씩 분석해 노트로 남기려면([사내 레거시 LLM 위키 워크벤치](/company-llm-wiki-workbench)), 분석 대상인 DDL이 로컬에 있어야 하고 그게 서버 최신본과 어긋나면 안 된다. 매번 전체를 다시 내려받는 건 느리고 변경 추적도 안 된다. 그래서 "마지막 가져온 시각 이후 바뀐 것만" 골라 갱신하는 증분 동기화 도구를 따로 깎았다.

이 작업은 로컬에서 초안(순수 로직)만 만들고, 실제 DB 접속은 사내 환경에서 붙인다. 집 저장소에는 실 접속 정보·실 객체명·실 DDL을 절대 들이지 않는다.

## 동작
1. 스키마의 객체 목록과 각 객체의 마지막 DDL 변경 시각을 조회한다.
2. 로컬 상태에 저장된 시각과 비교해 신규/변경만 골라낸다.
3. 신규·변경 객체는 메타데이터 추출로 DDL을 받아오고(실패 시 소스 재구성으로 폴백), 임시 파일에 쓴 뒤 원자적으로 교체한다.
4. DB에서 사라진 객체는 로컬 파일을 지우고 삭제 목록에 남긴다.
5. 객체별로 성공했을 때만 상태를 갱신한다. 그래서 실패한 객체는 다음 실행에서 자동 재시도되고, 바뀐 게 없으면 아무것도 받지 않는다(멱등).

## 핵심 결정

### 증분 + 멱등
전량 덤프 대신 마지막 가져온 시각 기준 증분으로 간다. 상태를 객체 단위로 성공 시에만 커밋하니, 중간에 끊겨도 다음 실행이 끊긴 지점부터 이어간다.

### 접속만 스텁, 나머지는 다 작성
DB 커넥션을 돌려주는 두 함수만 사내 환경에서 채우면 되도록, 접속을 제외한 변경 감지·DDL 추출·파일 레이아웃·삭제 처리·상태 관리는 전부 미리 구현했다. 사내에서 할 일이 "접속 연결 → 드라이런 → 타입별 확인"으로 좁혀진다.

### 메타데이터 추출 실패 시 소스 재구성 폴백
표준 메타데이터 추출이 비거나 DB 종류·버전에 따라 막히는 경우가 있어, 소스 기반으로 DDL을 재구성하는 폴백을 둔다. 그래도 안 되면 실패로 세고 계속 진행한다(한 객체 때문에 전체가 멈추지 않게).

## 현황
로컬에서 모듈 임포트와 도움말까지는 DB 드라이버 없이도 뜬다. DB를 실제로 건드리는 로직은 작성됐지만 라이브 접속으로 검증한 적은 없다. 테스트 코드는 아직 없다.

## 남은 일
- 사내 환경에서 접속 함수 두 개 구현 → 드라이런 → 타입별 점진 확인.
- 위키가 기대하는 입력 경로/포맷과 이 도구의 출력 경로/확장자를 맞추는 정합 작업.
