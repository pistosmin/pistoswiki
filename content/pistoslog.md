# pistoslog — 개인 블로그 겸 작업 아카이브

## 한 줄
그동안 만든 프로젝트와 블로그 제작 과정 자체를, 완성품 자랑이 아니라 판단·검증·시행착오 중심으로 기록하는 개인 블로그. Astro + React(아일랜드) + MDX 정적 사이트를 Codex로 만들어 GitHub Pages(https://pistosmin.github.io)에 띄웠다.

## 배경
Claude로 진행하던 작업환경을 Codex로 옮긴 직후(2026-05), 그동안 쌓인 프로젝트들을 어딘가에 정리해 두고 싶었다. 위키(pistoswiki)는 내가 보는 지식 저장소라면, 블로그는 바깥에 내놓는 글이다. 둘을 분리하되, 블로그는 "언제 무엇을 왜 만들었고 어디서 막혔는지"가 드러나는 타임라인으로 가져가기로 했다.

핵심 편집 방침은 두 가지다. 첫째, 각 글은 실제 개발한 날짜로 박는다. 한 번에 몰아 올린 듯 보이지 않게 진짜 시간 순서를 남긴다. 둘째, 압축하지 않는다. AI가 처음 써준 초안은 너무 요약적이어서 다 버렸고, 대화 로그에서 기술적 근거·테스트 단계·오래 걸린 실수를 끌어와 Medium/Velog 기술 시리즈 수준으로 풀어 썼다.

## 구조
- 정적 사이트 생성기는 Astro 6, 본문은 MDX(서사 + 코드), 인터랙션이 필요한 곳만 React 아일랜드.
- 콘텐츠는 두 컬렉션으로 나눴다. `posts`(카테고리: 일상/생각/기술공부/작업기록, 시리즈 묶음 지원)와 `projects`(상태/스택/링크). 프로젝트는 `links.caseStudy`로 대응 회고 글과 1:1로 묶인다.
- 검색은 서버 없이 도는 Pagefind 정적 인덱스, 배포·구독은 RSS·sitemap, 댓글은 백엔드를 안 띄우려고 GitHub Discussions 기반 giscus.
- 호스팅은 GitHub Pages. main에 push하면 Actions가 빌드해서 배포한다.

## 핵심 결정

### 무거운 굴절 효과를 걷어내고 정적 우선으로
처음엔 리퀴드 글래스(굴절) 효과를 런타임으로 넣었는데, 무거운 굴절 라이브러리 + `backdrop-filter`/blur + 전역 포인터 추적 + 전역 React 헤더 아일랜드가 겹치면서 로컬 스크린샷 캡처와 GitHub Pages 양쪽에서 브라우저가 죽었다. 진단은 명확했다. Astro/Pagefind/Pages 선택 자체는 옳았고, React를 과하게 쓴 *구현*이 문제였다. 그래서 얇은 정적 Astro 셸로 다시 짜고, 전역 헤더 아일랜드를 버리고, 검색·테마·굴절을 opt-in 아일랜드로 떼어냈다. 굴절 컴포넌트는 지금 의도적으로 아무 일도 안 하는 안전 shim이고, 글래스 룩은 순수 CSS로만 낸다.

### 추적 없는 집계 통계
글마다 반응/댓글 수를 보여주되, 방문자 식별자·IP·읽음 횟수 같은 건 서버에 남기지 않기로 했다. 반응·댓글 집계만 빌드 타임에 정적으로 박고, "읽음" 표시는 브라우저 localStorage에만 둔다. 원래 요청했던 IP 기반 좋아요 수 같은 건 이 원칙 때문에 범위에서 뺐다.

### 토큰 없는 정적 친화 유지
빌드 타임에 GitHub API를 호출하거나 토큰·서버·유료 의존을 추가하지 않는다. GitHub 기여 표시 같은 것도 토큰 없는 방식으로만 처리한다. 시크릿은 소스에 박지 않고 Actions 시크릿에만 둔다.

## 현황
사이트는 라이브 상태고 빌드도 정상이다. 글 12편, 프로젝트 8개가 올라가 있다. 제작 과정에서 무인 반복 루프(Ralph)로 백로그를 돌리려다, child 세션의 모델 접근이 막혀(권한 모드와 모델 접근은 다른 문제였다) 루프가 정지했고, 결국 같은 커밋 컨벤션으로 백로그 다섯 건을 수동 구현했다. 이 경험 자체도 블로그 글 하나로 남겼다.
